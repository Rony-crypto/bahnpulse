## Columns used

| Column | Type | Meaning | Notes |
| --- | --- | --- | --- |
| `id` | string | Stop-record identifier | Unique in the Nov 2025-Aug 2026 dbt build; preferred row key. |
| `eva` | string | Station identifier | Join to the DB StaDa station dimension for `federalState`. |
| `train_type` | string | Raw train/operator code | Map with `dbt/seeds/train_type_map.csv`; blank values are junk candidates. |
| `train_number` | string | Train number | Missing on the same 606,209 rows as blank `train_type` and missing `delay_in_min`. |
| `delay_in_min` | integer | Delay in minutes | Use for rail punctuality; exclude Bus and flag blank-type rows. |
| `train_line_ride_id` | string | Ride identifier | Repeats across service dates; not unique by itself. |
| `train_line_station_num` | integer | Stop position on a ride | Combine with service time for a stop candidate, but retain `id` as row key. |
| `arrival_planned_time`, `departure_planned_time` | timestamp | Scheduled stop time | Arrival is normally absent at the first stop; departure at the last. |
| `arrival_change_time`, `departure_change_time` | timestamp | Changed/observed stop time | Some values exist without the corresponding planned time; see profile counts. |
| `replaced_train_number` | string | Replaced service number | 99.32% null; expected for non-replacement trains. |

## Quirks found during profiling

- The profiled Jun-Aug 2026 files contain 44,367,234 rows (about 14.5-15.1 million per month). The local history window is Nov 2025-Aug 2026.
- Map raw operator codes to ICE, IC/EC, RE, RB, S, Bus, or Other with the dbt seed. Bus is rail replacement/service and is excluded from rail punctuality. Blank `train_type`, `train_number`, and `delay_in_min` each occur on 606,209 rows; flag/drop these junk candidates.
- Hamburg S-Bahn line counts join normalized EVA to DB StaDa `federalState = Hamburg`, not station-name prefixes, and exclude anomalous line S0. The current map covers all 5,445 distinct S1 EVAs; six historic stations use documented state overrides.
- Arrival and departure planned times are missing on about 9.2% of rows as expected at ride endpoints. There are 553,467 arrival and 560,834 departure change times without a corresponding planned time; investigate before deriving delay from timestamp differences.
- `id` is unique in the Nov 2025-Aug 2026 dbt build. `train_line_ride_id + train_line_station_num` is not unique across dates; adding planned time still leaves collisions in the Jun-Aug audit, so use `id` for row identity and validate any stop-level key further.
- Detect collection gaps from hourly stop **volume**, not from filled-delay/change-time shares: when a fetch hour is missed, the few stops that remain still have their delays filled, so the share stays normal and flags nothing. dbt mart `agg_month_coverage` flags hours with under half the usual volume for that weekday and hour of the month; months with 24+ such hours count as partial. Result: Nov 2025 (1–2 Nov, before full station coverage) and Jul 2026 (overnight 00–05 on 4, 7–9 and 21–23 Jul, at 2–5% of normal volume). No hour is fully empty, which is why a planned-stop presence check finds nothing.

## Current history window

The local pipeline contains monthly source files from Nov 2025 through Aug 2026. The Sept 2026
file was checked on Hugging Face on 2026-10-01 and returned HTTP 404. Event timestamps can extend
into September even though the latest published source file is August.
