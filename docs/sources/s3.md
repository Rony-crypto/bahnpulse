# S3: DB Station Data API (StaDa)

| Item | Value |
| --- | --- |
| Endpoint | DB API Marketplace Station Data v2, `GET /stations?searchstring=*&offset=...&limit=...` |
| Licence | CC BY 4.0, Deutsche Bahn AG |
| Update | Monthly refresh planned; station master data changes rarely |
| Current snapshot | 5,408 station records and 5,461 unique StaDa EVA numbers (2026-10-01) |
| Raw storage | `data/raw/s3/stations/<UTC snapshot>/page-*.json` |
| Derived lookup | `data/raw/s3/station_state_map.csv` |

## Fields used

StaDa `name`, `federalState`, `category`, and each `evaNumbers[].number` are retained in the
derived station lookup. Coordinates are read from each EVA's GeoJSON point in `[longitude,
latitude]` order. Raw API pages are saved separately from the normalized lookup.

## Quirks and handling

- S1's EVA strings are eight characters and begin with `0`; StaDa EVAs do not. The pipeline
  removes exactly that leading zero for S1 joins, while preserving the raw S1 value in staging.
- One current StaDa station record has no EVA number and is omitted from the EVA lookup.
- Six historical S1 stations are absent from the current StaDa result set: Harra Nord,
  Stollberg (Sachs),
  Lichtenstein (Sachs), Niederwürschnitz, Oelsnitz (Erzgeb), and Rödlitz-Hohndorf. Their state
  mappings are explicit in `config/station_state_overrides.csv` and labeled as manual in the
  derived lookup.
- The loader audits unique S1 EVA coverage and fails if any identifier remains unmapped.
- The Nov 2025-Aug 2026 files contain 5,445 distinct S1 EVAs; the generated lookup maps all of
  them (100%). The six overrides are added to the 5,461 current StaDa EVA mappings.
